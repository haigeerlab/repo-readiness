## 二、形态与实现

| # | 假设 | 理由 | 如果不成立 |
| --- | --- | --- | --- |
| A4 **【问】** | **核心是命令行工具**，所有判定、打分、报告、对比、接入结论都在 CLI 里完成；**Claude Code / Codex 插件只放一个薄 skill**：调用 CLI、完成第二段的 agent 裁决、把一屏摘要讲给用户、对"要人确认"的修复逐项征求同意 | CI 只能跑 CLI；把逻辑放进 skill 会出现两套判定。一个 skill 两个宿主共用（SKILL.md 格式相同） | 如果要 skill 独立判定，CI 结果和本机结果可能不一致 |
| A5 **【问】** | 实现语言：**Python 3.9+，只用标准库，零第三方依赖** | 本机实测：macOS 自带 `/usr/bin/python3` 是 3.9.6（随 Xcode 命令行工具提供），`/bin/bash` 是 3.2.57；GitHub Actions 的 ubuntu 镜像自带 python3。bash 3.2 做打分、schema 校验太吃力；Node 不是系统自带 | 选 Node：要求每台机器先装 Node；选 bash：schema 校验和打分要大量手写 |
| A6 | 因为 3.9 标准库**没有 YAML 和 TOML 解析器**：<br>① 本工具自己定义的格式（条款文件、检测报告、接入结论、裁决文件）一律 **JSON + JSON Schema 2020-12**；<br>② 被测仓库里标准规定为 YAML 的文件（`readiness.yml`、`interface.yml`、`risk-tiers.yml`）用**内置的 YAML 子集解析器**读：只支持块状映射、列表、行内 `{}` / `[]`、带引号和不带引号的标量、注释；遇到锚点、多文档、多行字符串块等不支持的语法，**明确报错（退出码 2）**，不猜；<br>③ JSON Schema 校验同样内置，只实现我们 schema 用到的关键字 | 零依赖；"不支持就报错"比"解析错了还当成功"安全。现有三个模板（`readiness.example.v2.yml`、`interface.example.yml`）都落在这个子集里 | 若标准要用更多 YAML 语法，要么标准侧收窄，要么改成 JSON；这条要通知 `autopr-standard`（接口清单 #10） |
| A7 | 工具**从不调用模型**。三段式第二段（agent 裁决）用"文件交接"：CLI 输出待裁决清单 → 宿主里的 agent 写裁决文件 → CLI 读回并校验 → 打分 | 模型不做算术、判定可复现；CLI 在 CI 里也能跑（没有裁决文件时，声明类条款沿用上一份报告或判"无法判定"） | — |
