## T16 中修掉的 3 处工具判错

第一轮对照暴露，修正并补了测试后重跑：

| 现象 | 原来 | 现在 | 修法 |
| --- | --- | --- | --- |
| session-protocol 没有远端，G2、G4、G5、G6 | 无法判定 | 不满足 | 所有 GitHub 探针先看仓库在不在 GitHub 上；不在就判不满足（没有设置可言），不再因为 404 判"读不到" |
| ai-dev-playbook 私有，平台不报告秘密扫描，G5 | 无法判定 | 不满足 | 平台不报告时，如果仓库连一个 workflow 都没有，就不可能有 CI 等效检查，判不满足；有 workflow 时仍是无法判定（等效检查本版判不了） |
| frontend-knowledge-tree 有锁文件但没有 CI，E1 | 不满足 | 满足（注明） | 与 spec-guard"CI 不装这类依赖"同样处理：只看锁文件；没有 CI 是 G3 的结论，E1 不重复扣分 |

另有一处是对照脚本自己的问题（没像 `check` 那样读 `readiness.yml`，导致每仓多出 5 个"探针错误"），已修。

## 需要 `autopr-standard` 确认的口径（汇总）

这次对照没有发现新的分歧，但下面几处是工具里的解读，下次去信一并确认：

1. E1：CI 不安装某类依赖（或根本没有 CI）时，只要锁文件在就满足。
2. G4：取 main 上最近一次任一 workflow 的运行（push / 定时 / 手动，不算 PR；取消和跳过不算结论）。
3. G2 绕过名单：团队判阻断；只有 admin（id 5）算管理员；个人账号判"存在绕过"。
4. G5：私有仓库平台不报告、又有 CI 时，"CI 等效密钥检查"本版判不了，记无法判定。
5. G9：没有 workflow 的仓库判满足（没有需要固定的 action）。
