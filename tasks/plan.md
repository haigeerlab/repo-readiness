## 概述

先做一条最细的纵向切片：玩具尺子 → 扫描 → 打分 → 报告 → 退出码 → 接入结论，把骨架打通；再按试点需要往里填探针。

用户已批准 Auto PR 的**切片 1**：以 agent-relay 为试点，准入脚本只读接入结论、把上限设为 L2，只报告模式运行。它向我要两样东西：
1. `schemas/conclusion.v1.json` 定稿，并有一个**带 tag 的发布版**（它按 tag + 40 位 SHA 引用）；
2. agent-relay 的**第一份接入结论**，没到基础档也行，L0 的结论正好用来测它的"没达标"路径。

所以计划把**接入结论提到第一阶段**，并在第二阶段中途设一个里程碑 M1：agent-relay 第一份结论。

只做试点要用的：基础档条款（G1–G7、V1、E1、D1、R1，外加建议项 V2、K1、R2）。标准档、高档的探针放到第一阶段验收之后。

## 架构决定（来自已批准的 Spec，只列影响顺序的）

1. Python 3.9 标准库，零依赖；`unittest`；所有子进程走同一个封装（无 stdin、有超时）。
2. 三份对外格式（条款文件、检测报告、接入结论）是 JSON + 内置 schema 校验。**它们是跨会话契约**：定稿时停一次请用户过目，再发给对方。
3. 打分、对比是纯函数，先写表驱动测试。
4. GitHub 只发 GET，全部经平台适配层；测试用录制的真实返回回放。
5. 执行被测仓库入口默认关闭；开了也只在临时 worktree 里跑。

## 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 结论 schema 发布后要改 | 高：切片 1 按 SHA 引用，改了要对方换引用 | 检查点 A 请用户和 `autopr-design` 都过目再打 tag；之后只加可选字段 |
| GitHub 权限、规则集口径判错 | 高：误判让仓库错掉档 | T10 先做，四类夹具（规则集、旧版、`evaluate`、权限不足）都是真实返回录制 |
| 自写 YAML 子集解析有漏洞 | 中 | 不支持的语法一律报错；用现有模板和坏样例测 |
| 执行被测仓库入口的安全风险 | 中 | 默认关；临时 worktree；跑后核对 git 状态；超时 |
| 标准 v2.0 仍是草案 | 中 | 不写死条款；变了只改尺子和夹具 |
| 测试只测到"会通过" | 中 | 每个探针、每条打分规则都要有"会失败"的用例 |
